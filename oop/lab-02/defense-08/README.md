# Защита второй лабораторной

Задание 8 с фотографии: класс «Кофейня» и наследник «Частная кофейня».

Из папки `oop`:

```bash
make defense2
make run-defense2
```

`make defense2` собирает защиту в `build/defense2`. `make run-defense2` собирает и сразу запускает её. Обычный `make` тоже собирает защиту вместе с лабораторными.

Ввод с клавиатуры не требуется. Пример демонстрирует оба конструктора каждого класса, изменение и чтение полей, наследование методов и виртуальный вызов `show`. Все сведения о кофейнях учебные.

## Как устроен код

`Cafe` — базовый класс. Он хранит название, телефон, адрес и время работы. Все поля имеют тип `string`: телефон может содержать плюс, дефисы и начальные нули, поэтому число для него не подходит.

`private` закрывает поля от прямого обращения из `main`. `public` делает конструкторы и методы доступными. Например, `first.name = "Утро"` нельзя, а `first.setName("Утро")` можно.

`Cafe()` — конструктор без параметров. При записи `Cafe first;` он заполняет четыре поля строками «Не указано». Конструктор не имеет типа возвращаемого значения и называется так же, как класс.

`Cafe(string n, string p, string a, string h)` — конструктор с параметрами. Он получает четыре значения и записывает их в поля объекта. В записи `Cafe second(...)` параметры идут в порядке: название, телефон, адрес, время работы. Два конструктора с разными параметрами — это перегрузка конструкторов.

Методы `setName`, `setPhone`, `setAddress`, `setHours` изменяют поля. Например, `setName(string n) { name = n; }` записывает переданное название. Тип `void` означает, что метод ничего не возвращает.

Методы `getName`, `getPhone`, `getAddress`, `getHours` возвращают поля. Например, `getName()` возвращает строку с названием. Сам метод ничего не печатает: печать выполняет `cout` в `main`.

`show()` выводит все четыре поля. Вызов `first.show()` показывает именно данные объекта `first`, а не всех кофеен сразу.

`class PrivateCafe : public Cafe` означает, что PrivateCafe наследуется от Cafe. Частная кофейня содержит четыре поля базовой части и своё поле `owner` — ФИО владельца. Публичные методы Cafe доступны объекту PrivateCafe. При этом закрытые поля Cafe нельзя читать напрямую даже из методов наследника; для этого есть методы get.

`PrivateCafe() : Cafe()` сначала вызывает конструктор базового класса без параметров. Затем тело конструктора заполняет владельца. Так у объекта инициализируются все пять полей.

В конструкторе с параметрами запись `: Cafe(n, p, a, h)` передаёт четыре значения конструктору базового класса. После этого `owner = o` заполняет дополнительное поле. У каждого объекта PrivateCafe есть одна базовая часть Cafe, а не отдельная вторая кофейня.

`setOwner` меняет владельца, `getOwner` возвращает владельца. Остальные методы set и get наследуются, поэтому переписывать их не нужно. В `main` вызов `fourth.setName(...)` показывает использование унаследованного метода.

`show()` в наследнике переопределён. Сначала `Cafe::show()` явно вызывает метод базового класса и печатает четыре общих поля. Затем печатается ФИО владельца. Двоеточия `::` указывают, метод какого класса вызывается. Если вместо `Cafe::show()` написать здесь просто `show()`, метод будет вызывать сам себя.

`virtual` у базового `show` позволяет выбирать метод по реальному типу объекта, даже при обращении через указатель Cafe. `override` у метода наследника просит компилятор проверить, что этот метод действительно переопределяет базовый виртуальный метод.

В конце `main` запись `Cafe* cafe = &fourth` создаёт указатель на уже существующую частную кофейню. `&fourth` — её адрес. `cafe->show()` вызывает show через указатель. Благодаря virtual выполняется PrivateCafe::show, поэтому выводится и владелец. Объект не копируется. Операторов new и delete здесь нет.

## Что происходит в main

1. Создаются обычные кофейни `first` и `second`: без параметров и с параметрами.
2. Выводятся их начальные данные.
3. У `first` меняются все четыре поля через set, затем читаются через get.
4. Создаются частные кофейни `third` и `fourth` с обоими конструкторами и выводятся все пять полей.
5. У `fourth` меняются название унаследованным методом и владелец собственным методом.
6. Через указатель Cafe вызывается вывод PrivateCafe. Последний блок показывает новое название и нового владельца.

## Что сказать преподавателю

Я создал базовый класс Cafe с четырьмя закрытыми полями. В нём есть два конструктора, методы изменения и получения полей и метод вывода. Класс PrivateCafe наследуется от Cafe и добавляет ФИО владельца. Его конструктор вызывает конструктор базового класса. Метод show переопределён: он выводит общие данные и владельца. В main я проверяю оба конструктора и работу методов. В конце вызываю show через указатель на базовый класс, чтобы показать полиморфизм.

## Короткие ответы

- Класс — описание данных и действий; объект — конкретная кофейня, созданная по этому описанию.
- Наследование — получение базовой части и доступных методов другим классом.
- Перегрузка — несколько функций с одинаковым именем, но разными параметрами. Здесь перегружены конструкторы.
- Переопределение — собственная реализация базового виртуального метода у наследника. Здесь переопределён show.
- Полиморфизм — вызов разных реализаций через общий базовый тип. Здесь указатель Cafe вызывает вывод PrivateCafe.
- Публичное наследование сохраняет публичные методы базового класса публичными у наследника.
