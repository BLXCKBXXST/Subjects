# Объяснение третьей лабораторной

В третьей лабораторной работе у меня вариант 24. Нужно вывести ведомость закупок чая из бинарного файла и определить, в какой упаковке чай продаётся лучше. Я сравниваю упаковки по общему количеству проданных единиц.

Для одной записи я создал класс `Tea`. В нём хранятся тип чая, упаковка, производитель, цена и количество. Метод `total()` умножает цену на количество и возвращает сумму одной строки. Метод `show()` выводит все сведения о записи.

Текстовые поля представлены массивами `char`, чтобы объект можно было записать в бинарный файл целиком. Если использовать `string`, простая запись всех байтов объекта не сохранит текст правильно.

Работа разделена на две программы. Первая программа, `create.cpp`, создаёт бинарный файл. Сначала она открывает `tea.txt` для чтения. Переменная `text` — это файловый поток, через который программа читает исходные данные.

Первым числом из файла считывается количество записей `n`. Затем создаётся поток `binary`, который открывает `tea.bin` для записи в бинарном режиме. В начало бинарного файла записывается количество записей, чтобы вторая программа знала, сколько объектов нужно прочитать.

Дальше выполняется цикл на `n` повторений. На каждом повторении создаётся объект `tea`. Команда `text >> ws` пропускает пробелы и переводы строк перед текстом. Затем в объект считываются три текстовых поля через `getline`, а цена и количество — через оператор `>>`.

Команда `binary.write((char*)&tea, sizeof(tea))` записывает объект в файл. Здесь `&tea` — адрес объекта, а `sizeof(tea)` — его размер в байтах. Преобразование к `char*` позволяет передать эти данные методу записи как последовательность байтов. После записи всех объектов файл закрывается.

Вторая программа, `process.cpp`, открывает полученный бинарный файл для чтения. Сначала она считывает `n`. Если записей нет, выводится сообщение о пустой ведомости.

После чтения `n` создаётся массив `teas` из `n` объектов. Обычный цикл читает по одному объекту командой `binary.read((char*)&teas[i], sizeof(Tea))`. Здесь `&teas[i]` — адрес очередного объекта, а `sizeof(Tea)` — сколько байтов нужно прочитать. После цикла проверяется, удалось ли прочитать все записи.

Для подсчёта используются два небольших массива. В `packages` заранее записаны четыре упаковки из таблицы задания: «Пачка», «Пакетики», «Жесть», «Фарфор». В `counts` хранятся их количества, сначала все они равны нулю. Например, `packages[0]` содержит «Пачка», а `counts[0]` — общее количество пачек.

Внешний цикл перебирает чаи из массива `teas`. Внутренний цикл перебирает четыре упаковки. Если название совпало, количество этого чая добавляется к соответствующему элементу `counts`. Поэтому 50 и 89 пачек из двух записей складываются в 139. Программа рассчитана на четыре вида упаковки из задания.

По методичке результат нужно вывести после повторного чтения бинарного файла. Поэтому команда `seekg(sizeof(n))` возвращает позицию чтения к первой записи, пропуская число `n` в начале файла. Затем такой же цикл `read` снова заполняет элементы массива, выводит ведомость и складывает суммы строк. Первый проход нужен для подсчёта упаковок, второй — для вывода по условию работы.

После этого программа находит максимальное значение в массиве `counts` и выводит соответствующую упаковку. Если несколько упаковок имеют одинаковый максимум, выводятся все. Если все количества равны нулю, программа сообщает, что продаж нет.

На исходных данных лучше продаётся чай в пачках: 50 плюс 89, всего 139 единиц. В пакетиках получается 111, в жестяной упаковке — 23, в фарфоровой — 76.

В программах проверяются открытие файлов, количество записей и успешность чтения. В конце второй программы `delete[] teas` освобождает память массива чая. Для двух небольших массивов размером четыре элемента `delete[]` не нужен.
