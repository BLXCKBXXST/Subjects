# Практика 4 — FIFO, вариант 6

Клиент отправляет имя текстового файла. Сервер находит слово с максимальным количеством строчных русских букв «а», записывает слово и количество букв в `output.txt`, затем отправляет клиенту имя результата. Клиент открывает этот файл и показывает его содержимое.

Задание и пример `input.txt` взяты из практики 3. При одинаковом максимуме выбирается первое слово. Исходный текст — строчные русские буквы и пробельные разделители, не длиннее 4999 байт UTF-8. Если слов нет, результат — «Слов нет.».

Две отдельные программы: `server.c` и `client.c`. В `common.h` заданы имена каналов, файла результата, размеры строк и формат запроса. `fork()` здесь не используется.

## Запуск

В обоих терминалах нужно находиться в папке `operating-systems/practice-04`.

Сначала собрать:

```bash
make
```

В первом терминале:

```bash
make run-server
```

Сервер напишет, что ждёт клиента. Это нормальное ожидание.

Во втором терминале:

```bash
make run-client
```

Когда клиент спросит имя файла, ввести:

```text
input.txt
```

Либо передать имя сразу:

```bash
printf 'input.txt\n' | ./client
```

Результат:

```text
Файл результата: output.txt
Слово: абракадабру
Количество букв 'а': 4
```

Один запуск сервера обслуживает один запрос. Для следующего запроса снова запустить сервер. После завершения сервер удаляет FIFO. После принудительной остановки удалить оставшиеся каналы командой `make clean`, затем снова выполнить `make`. `make run` также запускает сервер, клиент всё равно запускается во втором терминале.

## Обмен

Для запроса и ответа используются два однонаправленных канала: `request.fifo` и `response.fifo`. Сервер создаёт их через `mkfifo`. Клиент отправляет запрос через `open`, `write` и `close`. Сервер читает запрос, а клиент читает ответ через `fopen` и `fgets`, как из потока.

Формат имени из методички оформлен строкой в кавычках: `«input.txt»` и перевод строки. Кавычки добавляет клиент, пользователь вводит только имя. Сервер пропускает всё до первой пары `«...»`, включая посторонние строки перед запросом.

Сервер читает файл, считает буквы, закрывает `output.txt` и только после этого передаёт его имя клиенту. Если обработка не удалась, вместо имени передаётся `ERROR`.

Пути к исходному файлу и результату считаются от текущей папки запуска. Файл с пробелами в имени тоже можно указать. Сервер и клиент запускаются в одной папке на одном компьютере.
