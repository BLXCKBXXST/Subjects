# Практика 2

Программа показывает первые 10 переменных окружения и содержимое указанного файла. В конце выводит ФИО автора и UID пользователя, который её запустил.

Из этой папки:

```bash
make
make run
```

`make run` запускает `./practice -1 -f example.txt`. Отдельные примеры:

```bash
./practice -1
./practice -2
./practice -2 -f example.txt
./practice -1 -2
./practice -f example.txt -f example.txt
```

`-1` получает окружение через третий параметр `main`, `envp`. `-2` получает его через глобальную переменную `environ`. Полученные строки обычно одинаковые: это окружение одной программы. Если переменных меньше десяти, выводятся все доступные. `make run1` и `make run2` запускают эти способы отдельно.

`-f` берёт имя файла из `optarg`. Файл выводится посимвольно: `fgetc` читает символ, `putchar` печатает его. Каждая опция выполняется по очереди; можно вывести оба способа или несколько файлов. Для имени с пробелами нужны кавычки: `./practice -f "мой файл.txt"`.

`main.c` содержит весь код, а `practice.h` — подключения библиотек и объявления функций и `environ`. Третий параметр `main` используется как в методичке; это вариант для Linux/GCC.

Для проверки ошибок:

```bash
./practice -z
./practice -f
./practice -f missing.txt
./practice -f .
```

Сообщения об ошибках идут в `stderr`. Проверяются открытие, чтение, вывод и закрытие файла. `fflush(stdout)` отправляет накопленный текст на вывод и позволяет заметить ошибку, которая не возникла сразу при `putchar`.

В `main` есть один `return` в самом конце, поэтому сведения об авторе выводятся и после ошибки. UID получается через `getuid`, а не задаётся заранее. Если `stdout` перестал работать, сведения об авторе выводятся через `stderr`. Строка `signal(SIGPIPE, SIG_IGN)` позволяет обработать ошибку закрытого канала вывода, не завершив программу раньше этой печати.

Код завершения: `0` — успешно, `1` — ошибка. После запуска его можно посмотреть командой `echo $?`. Сборка требует `gcc` и `make`. Удаление собранной программы: `make clean`.
